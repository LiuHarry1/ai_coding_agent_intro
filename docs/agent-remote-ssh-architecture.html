Baize Agent：Remote-SSH 架构设计

目标：选一台电脑 → 指定远程目录为 workspace → UI 本地、工具在远端执行（对标 VS Code Remote-SSH）。

参考：VS Code / GitHub Codespaces 公开架构 + Claude Code claude ssh + 本仓库现状。

优先 SSH 路径 对齐 CC AuthProxy 复用现有 Chat/Tools 非完整 IDE Server

01 问题定义

要对齐的体验

Connect to Host… → atsrws0049 Open Folder… → /home/…/ws-code_index 标题栏 → [SSH: atsrws0049] 文件 / Bash / Agent tools 全部在远端执行

本仓库现状

能力现状
Workspace本机或 Docker 挂载路径（WORKSPACE / 请求体）
Agent 进程与 HTTP API 同机；工具直接碰本地盘
客户端Web / Electron / CLI / ACP
Remote-SSH无运行时；仅有 CC 逆向文档
设计原则

Coding Agent ≠ IDE。我们要 Agent Runtime 远端化，不是搬完整 VS Code Extension Host。

对齐 CC：UI 本地 · 工具远端 · AuthProxy 护凭证 · Session 绑定 remoteCwd。

03 推荐架构

一句话

本地 Controller 通过 SSH 在目标机拉起 Agent Worker；Session 绑定 { hostId, remoteCwd }；聊天与工具流经隧道；权限弹窗回本地。

┌─ Client: Web / Electron ─────────────────────────────┐ │ Host picker · Folder picker · Chat · Permission UI │ └────────────────────────┬─────────────────────────────┘ │ HTTP / WS ▼ ┌─ Local Controller（现有 agent 编排侧扩展）────────────┐ │ SessionStore + RemoteBinding · SshHostRegistry │ │ RemoteSessionManager · AuthProxy · Workspace 双后端 │ └────────────────────────┬─────────────────────────────┘ │ SSH exec + -R AuthProxy ▼ ┌─ Remote Agent Worker ────────────────────────────────┐ │ ~/.baize-agent-worker/<ver>/ · cwd = remoteCwd │ │ 现有 Tools · stream-json · 无长期明文 API Key │ └──────────────────────────────────────────────────────┘

与现有代码映射

现有模块Remote 模式变化
workspace.ts / request-cwd.ts有 remote binding 时转发 Worker，不本地 resolve
session/store.ts增加 remote?: { hostId, remoteCwd, workerVersion }
workspace/router.tslist/stat 支持 local | ssh 后端
Web HeaderConnect Host → Open Folder；标题 [SSH: host]
Electron第一期主战场（本机有 SSH keys）
Docker SSO 钉目录与 Remote-SSH 场景分流，不混为一谈

核心类型

type SshHostConfig = {
  id: string; name: string; sshHost: string;
  sshUser?: string; sshPort?: number; sshIdentityFile?: string;
  proxyJump?: string; startDirectory?: string;
}

type RemoteBinding = {
  hostId: string; remoteCwd: string;
  workerVersion: string; connectedAt: string;
}

04 连接时序

1. Connect to Host → atsrws0049 2. 解析 SshHostConfig / ~/.ssh/config 3. SSH 连通探测 4. Probe Worker → 无则 deploy 到 ~/.baize-agent-worker/<ver>/ 5. 本地启 AuthProxy 6. ssh -R + 远端启动 worker --cwd <dir> 7. Handshake → realpath(remoteCwd) 8. （可选）Open Folder 列远端目录 9. Session.remote = { hostId, remoteCwd, … } 10. Chat → Controller → SSH stream → Worker tools permission ask → 本地 UI → control_response

05 协议

段协议说明
Browser ↔ Controller现有 REST + 流式前端少改；Session 带 remote 元数据
Controller ↔ WorkerNDJSON stream-json 子集（抄 CC）经 SSH 转发；含 control_request/response

Controller 做协议适配器：对内像「又一个本地 agent 后端」，Web UI 几乎不用重写工具渲染。

06 Workspace 语义

概念含义
uiWorkspaceLabelatsrws0049:/home/…/ws-code_index
executionCwdWorker 进程 cwd
sandbox root在 Worker 内校验；不能用本机 realpath 校验远端路径
  • Remote Session 忽略客户端乱传的本地 workspace
  • 换远端文件夹 → 重启 Worker（简单可靠）
  • 历史仍存 Controller .sessions/；路径字符串为远端路径

07 安全

  1. AuthProxy 本地化：API Key 不落远端环境变量
  2. SSH 走用户自己的 key / ssh-agent
  3. 危险工具权限弹窗仍在本地（对齐 CC useSSHSession）
  4. Web SSO 用户通常无内网 SSH → 第一期仅 Electron/本机 CLI
  5. 审计：记录 hostId + remoteCwd + user

08 分阶段落地

Phase 0 — 契约与假远端

类型 + settings；--remote-local（对齐 CC --local）本机双进程跑通协议与权限回传。

Phase 1 — 真 SSH MVP

Host picker、probe/deploy、ssh -R + AuthProxy、Electron 标题 [SSH: host]、Chat 全走 Worker。

Phase 2 — 打磨

重连、端口转发（预览）、ProxyJump、Host 级 settings。

Phase 3 — 可选

Bridge 反向注册；CCR 式云环境——另立项。

CC 路径采用？原因

11 验收标准

  1. 选 atsrws0049，打开远端目录，标题 [SSH: atsrws0049]
  2. Agent 改的文件出现在远端，本机无副本
  3. hostname / pwd 显示远端主机与 remoteCwd
  4. 权限弹窗在本地；Deny 后远端不执行
  5. 远端看不到完整 LLM API Key
  6. --remote-local 可不依赖真 SSH 做回归

12 总结

Bottom line

业界：VS Code = 本地 UI + 远端 Server + SSH；Codespaces = 云托管版。

CC：同一不变量，远端跑 Agent CLI + AuthProxy——更适合我们。

我们：现有 Controller 上加 RemoteSessionManager + AuthProxy + Worker deploy；Session 绑 host + remoteCwd；UI 做 Host/Folder picker。

第一期不做完整 Extension Host，也不让 Web SSO 直连 SSH。
