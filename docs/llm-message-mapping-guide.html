4完整一轮 Tool Call → Tool Result

以读取文件 read_file 为例，三种格式并排对照。

4.1 08-basic 持久化格式（AI SDK 风格）

// services/tools/tool_execution.ts → buildToolMessage()
[
  {
    "role": "assistant",
    "content": [
      { "type": "text", "text": "Let me read the file." },
      {
        "type": "tool-call",
        "toolCallId": "call_abc123",
        "toolName": "read_file",
        "input": { "path": "src/main.ts" }
      }
    ]
  },
  {
    "role": "tool",
    "content": [
      {
        "type": "tool-result",
        "toolCallId": "call_abc123",
        "toolName": "read_file",
        "output": { "type": "text", "value": "export function main() { ... }" }
      }
    ]
  }
]

4.2 Anthropic 原生 wire format

// POST /v1/messages — 注意 tool_result 在 user 里，无 role:"tool"
{
  "model": "claude-sonnet-4-6",
  "system": "You are a coding assistant...",
  "tools": [{ "name": "read_file", "input_schema": { ... } }],
  "messages": [
    {
      "role": "user",
      "content": "What's in src/main.ts?"
    },
    {
      "role": "assistant",
      "content": [
        { "type": "text", "text": "Let me read the file." },
        {
          "type": "tool_use",
          "id": "toolu_01ABC...",
          "name": "read_file",
          "input": { "path": "src/main.ts" }
        }
      ]
    },
    {
      "role": "user",
      "content": [
        {
          "type": "tool_result",
          "tool_use_id": "toolu_01ABC...",
          "content": "export function main() { ... }"
        }
      ]
    }
  ]
}

4.3 OpenAI Responses API（08-basic 默认 openai provider）

// POST /v1/responses — 08-basic 使用 client.responses(id)
{

  "tools": [{ "type": "function", "name": "read_file", "parameters": { ... } }],

6System Prompt 与 <system-reminder>

Anthropic / Claude Code

  • 全局指令 → 顶层 system
  • Skills / deferred tools 列表 → 注入为 user 文本，包在 <system-reminder> 里
  • 不是独立 message role

OpenAI Responses

  • 全局指令 → instructions
  • 中途追加 → 新 instructions input item
  • Reasoning item 需 itemId replay（08-basic 会 strip）

08-basic 做法

  • systemPrompt(cwd, rules) → streamText({ system })
  • skillListing → user message with reminder tags
  • Plan mode 切换 → refreshSystemPrompt()
// 08-basic: runAgent() 注入 skill listing — 仍是 role:"user"
{
  "role": "user",
  "content": "<system-reminder>\nAvailable skills: read, write, bash\n</system-reminder>"
}

708-basic 发给 SDK 前的四步预处理

入口：core/agent.ts → runOneStep()， 在 streamText({ messages }) 之前执行（顺序固定）。

1 inlineReasoningAsText — 把 reasoning part 转成 <thinking>…</thinking> 文本，避免无状态代理 404
2 regroupToolResults — 把 tool-result 挪到对应 assistant tool-call 之后（CC 风格配对）
3 ensureToolResultPairing — 缺 result 则合成 placeholder；孤儿 result 则删除
4 applyCacheControlBreakpoint — Anthropic prompt caching：最后一条 message 打 cache_control: ephemeral
第 3 步的 synthetic result 文案： [Tool result missing due to internal error] （定义于 messageSanitize.ts）

10常见错误与 400 原因

症状根因08-basic 对策
Anthropic: tool_use_id 不匹配 result 的 id 与 call 不一致，或顺序错乱 regroupToolResults + ensureToolResultPairing
Anthropic: 连续两个 assistant tool_result 误标为 assistant，或缺 user 轮次 持久化只用 user/assistant/tool 三种 SDK role
OpenAI Responses: item_reference 404 重放 encrypted reasoning / item id 但上游无状态 sanitizeReasoningParts + inlineReasoningAsText
Chat: tool_calls 无对应 tool message 流中断在 call 与 result 之间 合成 SYNTHETIC_TOOL_RESULT_PLACEHOLDER
Compaction 后配对断裂 删了 assistant call 但留了 tool result microCompact 只清 payload，保留 message 骨架与 id

11一句话速记

AI SDK 用 user / assistant / tool 三种 message role， content 里用 tool-call 和 tool-result part 类型。
Anthropic 只有 user / assistant（+ 可选中途 system）； 工具结果是 user 消息里的 tool_result block，没有 tool role。
OpenAI Responses 用扁平 input[] items（function_call + function_call_output）； Chat Completions 用 assistant.tool_calls + role: tool message。
08-basic 在 SDK 层统一建模，发送前 sanitize；执行后 buildToolMessage() 回写；Claude Code 行为在 wire 层与 Anthropic 一致。
