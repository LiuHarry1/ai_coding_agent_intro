AI Agent Web Search 实现对比

搜索后端（SearXNG / Exa / Tavily / Provider 原生）、各主流 Coding Agent 的选型， 以及本仓库 examples/08-basic 的可切换实现。

1先分清两种能力

几乎所有 Agent 都把「发现链接」和「读页面正文」拆成两步，只是命名不同。

Discovery — 发现

  • 工具名常见：web_search / WebSearch / websearch
  • 输入：自然语言 query
  • 输出：标题、URL、snippet / highlights
  • 后端：SearXNG、Exa、Tavily、Anthropic/OpenAI 服务端工具等

Retrieval — 抓取

  • 工具名常见：web_fetch / WebFetch
  • 输入：已知 URL
  • 输出：正文、Readability 提取、或 Tavily Extract
  • 与搜索解耦：先搜再 fetch，或 Exa/OpenAI 一次返回更多正文
架构模式：Client-side tool（Agent 自己调搜索 API） vs Server-side / Hosted tool（模型厂商 API 内执行，客户端只解析结果块）。

2搜索后端对比

面向 Agent 集成时的维度：是否要 Key、免费额度、返回格式、中文/实时新闻表现。

后端 类型 免费额度（概览） 集成方式 优点 缺点
SearXNG 自托管 无 API 费（需自己运维） HTTP /search?format=json 隐私可控、可配引擎、零边际成本 引擎易挂、中文/娱乐类常 0 结果、要 Docker
Exa SaaS MCP 匿名 ~50–150 次/天/IP；配 Key 后 API ~2 万/月 REST 或 MCP web_search_exa 语义搜索、长 Highlights、live crawl、中文实时内容较好 非无限免费；MCP 解析略复杂
Tavily SaaS ~1000 credits/月（basic 搜索 ≈ 1 credit） REST api.tavily.com 专为 Agent 设计、JSON 规整、可选 AI answer、Extract/Crawl 必须 Key；免费档比 Exa 配 Key 后更紧
Parallel SaaS 需 PARALLEL_API_KEY MCP search.parallel.ai/mcp OpenCode 可选第二后端 需付费 Key；生态小于 Exa/Tavily
Brave Search API SaaS 有免费档（按 Brave 政策） REST 便宜、快；OpenClaw 等支持 偏传统关键词搜索
Anthropic Server Tool Hosted 含在 Anthropic API 用量（~$0.01/次量级） Messages API web_search_20250305 零自建；Claude Code 官方路径 仅 Anthropic 生态；底层引擎不公开
OpenAI Responses web_search Hosted 含在 OpenAI/Copilot 订阅或 API Responses API web_search_call 与 GPT 深度集成 Copilot 第三方 API 通常不支持暴露此工具
DuckDuckGo HTML 抓取 免费、无 Key HTML scraping Pi 扩展 pi-websearch 默认后端 不稳定、无官方 API、易变
都不是「无限免费」：Exa 无 Key 有日限；Tavily 约 1000 次/月；SearXNG 免费但你要扛运维与引擎质量。

4架构对照（三种典型路径）

┌─────────────────────────────────────────────────────────────────────────┐
│ A. Client-side 搜索（本仓库 / OpenCode / OpenClaw / Tavily REST）        │
├─────────────────────────────────────────────────────────────────────────┤
│  User → LLM → tool_call(web_search)                                      │
│           → Agent 进程 → Exa MCP / SearXNG / Tavily API                  │
│           → 结构化 JSON 回到 context →（可选）web_fetch(URL)            │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ B. Server-side Hosted（Claude Code WebSearch）                           │
├─────────────────────────────────────────────────────────────────────────┤
│  User → LLM → Agent 再发 Anthropic API + web_search_20250305 schema      │
│           → Anthropic 服务端执行搜索                                      │
│           → web_search_tool_result 流式返回 → 映射为 tool result         │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ C. Provider-native + 扩展回退（Pi + pi-websearch）                       │
├─────────────────────────────────────────────────────────────────────────┤
│  OpenAI/Anthropic 模型 → 用 provider 内置 web_search（hosted）           │
│  其它模型 → DuckDuckGo HTML 或配置 Exa/Tavily/…                         │
└─────────────────────────────────────────────────────────────────────────┘

Discovery 与 Retrieval 可合并（Exa contents / Tavily extract）或拆分（SearXNG + web_fetch）。

5分产品细节

Claude Code

源码路径：WebSearchTool.ts → 注册 type: web_search_20250305，通过 queryModelWithStreaming 触发 Anthropic 服务端搜索。 客户端不调用 Exa/Tavily。Beta header： web-search-2025-03-05（Vertex/Foundry）。

OpenCode

packages/opencode/src/tool/websearch.ts： Exa MCP（web_search_exa）与 Parallel MCP 二选一； 默认 OpenCode provider 启用，其它 provider 需 OPENCODE_ENABLE_EXA。 与 webfetch 分工明确（文档：discovery vs retrieval）。

OpenClaw

基于 Pi 框架，搜索是一等配置项： tools.web.search.provider 可选 tavily、exa、brave 等； 另有 tavily_search / tavily_extract 插件工具做高级参数。 Exa 支持 contents 一次返回摘要，减少二次 fetch。

Pi Agent

pi-coding-agent 本体只有 read/write/bash 等文件工具； 搜索靠 pi.registerTool() 扩展。 社区 pi-websearch： OpenAI/Anthropic 会话自动 defer 到 provider-native search，其它走 DuckDuckGo 或配置文件里的多 provider 链。

Cursor

Agent 联网能力主要来自 MCP 生态，而非单一开源 core： exa-cursor-plugin、 tavily-cursor-plugin 提供 Search / Fetch / Crawl / Research 等命令与 MCP。 典型 MCP 配置： 

{
  "mcpServers": {
    "exa": { "url": "https://mcp.exa.ai/mcp" },
    "tavily-mcp": {
      "command": "npx",
      "args": ["-y", "tavily-mcp@latest"],
      "env": { "TAVILY_API_KEY": "tvly-..." }
    }
  }
}

本仓库 examples/08-basic

实现目录：tools/web-search/（config / searxng / exa / index）。 切换方式： 

# .env
WEB_SEARCH_PROVIDER=exa       # 默认
WEB_SEARCH_PROVIDER=searxng   # 自托管 SearXNG

SEARXNG_URL=http://localhost:8888
EXA_API_KEY=                  # 可选，提高 Exa 配额

空结果时会返回 warning 字段，提示模型勿编造； UI 见 client/web/src/components/WebSearchCard.jsx。

6怎么选（给 Agent 作者）

优先 SearXNG

  • 内网 / 多租户 / 零 API 成本
  • 已有 Docker + 引擎维护能力
  • 配合 web_fetch 读正文

优先 Exa

  • 中文实时新闻、语义检索
  • 想对齐 OpenCode 实现（MCP）
  • 可无 Key 试用，正式用配 Key

优先 Tavily

  • 要最规整的 Agent JSON + optional answer
  • OpenClaw / LangChain 生态一致
  • 月 <1000 次搜索的固定配额可接受

用 Provider Hosted

  • Claude Code 式：只走 Anthropic API
  • 不想维护任何搜索基础设施
  • 接受 vendor lock-in 与按次计费
本仓库默认：Exa MCP（WEB_SEARCH_PROVIDER=exa）； 内网/零 API 成本场景改 searxng；若后续要 Tavily，可仿照 exa.ts 增加 REST provider 与同一 env 开关。
