1 概述

Claude Code（以下简称 CC）的扩展体系不是单一配置文件，而是多层 scope + 多种 loader + memoized cache 的组合。核心设计原则：

  • Scope 分层：Managed（企业策略）→ User（~/.claude）→ Project（.claude/）→ Local（gitignored）→ Plugin → Flag/CLI
  • 共享发现层：markdownConfigLoader.ts 统一扫描 .claude/{agents,skills,commands,...}
  • 专用 loader：Plugins 走 pluginLoader.ts + 各 component loader；MCP 走 services/mcp/config.ts
  • 缓存 + 热重载：Boot 时 memoize 加载；Skills 文件 watcher、/reload-plugins 可刷新
  • 两种冲突策略：Commands/Skills 用先注册先匹配；Agents 用后层覆盖前层

注意

CC 没有名为 component-loader 的模块。Plugin 组件刷新由 refreshActivePlugins() 统一 orchestrate。也没有原生 AGENTS.md loader——项目记忆走 CLAUDE.md 和 .claude/rules/。

2 目录布局

2.1 配置根目录

默认 home：~/.claude/（getClaudeConfigHomeDir()，可用 CLAUDE_CONFIG_DIR 覆盖）

2.2 User scope — ~/.claude/

~/.claude/ ├── settings.json # 用户级 settings（可被 project/local 覆盖） ├── skills/<name>/SKILL.md # 用户 skills ├── commands/ # 旧版 slash commands（deprecated 布局） ├── agents/*.md # 自定义 subagent ├── CLAUDE.md # 全局用户 memory ├── rules/*.md # 用户 rules（支持 paths 条件） ├── plugins/ # 已安装 plugin 缓存 └── .claude.json # 全局 app 状态（OAuth、projects map、user MCP）

2.3 Project scope — 从 cwd 向上 walk 到 git root

<repo>/ ├── CLAUDE.md # 项目 memory（checked-in） ├── CLAUDE.local.md # 本地 memory（gitignored） ├── .mcp.json # 项目 MCP（walk root → cwd，需 approved） └── .claude/ ├── settings.json # 共享项目 settings ├── settings.local.json # 本地 settings（gitignored） ├── skills/<name>/SKILL.md ├── commands/ # deprecated ├── agents/*.md └── rules/*.md # 条件 + 无条件 rules

2.4 Managed / Enterprise scope

平台路径
Linux/etc/claude-code/
macOS/Library/Application Support/ClaudeCode
WindowsC:\Program Files\ClaudeCode

包含 managed-settings.json、managed-settings.d/*.json、.claude/{agents,skills,...}、CLAUDE.md、managed-mcp.json（存在时独占所有 MCP）。

2.5 Plugin 目录结构

my-plugin/ ├── .claude-plugin/plugin.json # manifest（Zod 校验） ├── commands/ # slash commands 或 skill dirs ├── skills/<name>/SKILL.md ├── agents/*.md ├── hooks/hooks.json ├── .mcp.json └── output-styles/ # 可选

安装缓存：~/.claude/plugins/（或 CLAUDE_CODE_PLUGIN_CACHE_DIR）。Session 临时 plugin：--plugin-dir CLI 注入。

3 Settings 加载

CC 使用 settings.json 级联，而非单一 config.json。全局 app 状态在 ~/.claude/.claude.json（legacy fallback：.config.json）。

3.1 Settings 合并顺序（低 → 高）

优先级Source文件/来源
1（最低）Plugin settingsPlugin manifest 中 allowlisted keys
2userSettings~/.claude/settings.json
3projectSettings.claude/settings.json
4localSettings.claude/settings.local.json
5flagSettings--settings / SDK inline
6（最高）policySettingsmanaged-settings（first source wins，不 merge）

定义于 src/utils/settings/constants.ts 的 SETTING_SOURCES。入口：getInitialSettings() / loadSettingsFromDisk()。

3.2 全局 config（.claude.json）

getGlobalConfig() / getCurrentProjectConfig() 在 src/utils/config.ts：存储 OAuth token、per-project overlay（含 local MCP）、theme、migrations 等。与 settings 级联是两套系统。

4 Agents 加载

4.1 入口函数

// src/tools/AgentTool/loadAgentsDir.ts
export const getAgentDefinitionsWithOverrides = memoize(async (cwd) => {
  const markdownFiles = await loadMarkdownFilesForSubdir('agents', cwd)
  const customAgents = markdownFiles.map(parseAgentFromMarkdown)
  const pluginAgents = await loadPluginAgents()
  const allAgentsList = [...builtInAgents, ...pluginAgents, ...customAgents]
  const activeAgents = getActiveAgentsFromList(allAgentsList)
  return { activeAgents, allAgents, failedFiles }
})

4.2 文件发现（loadMarkdownFilesForSubdir）

扫描顺序（全部加载，再按 source 去重）：

  1. policySettings — /etc/claude-code/.claude/agents/
  2. userSettings — ~/.claude/agents/
  3. projectSettings — <ancestor>/.claude/agents/（cwd → git root，deepest first）

Walk 边界由 getProjectDirsUpToHome() 决定：默认停在最近 git root；子模块场景有特殊 widen 逻辑。

4.3 名称冲突 — 后层覆盖前层

// getActiveAgentsFromList — 按 source tier 顺序写入 Map
const agentGroups = [
  builtInAgents,    // 最低
  pluginAgents,
  userAgents,
  projectAgents,
  flagAgents,
  managedAgents,    // 最高
]
for (const agents of agentGroups) {
  for (const agent of agents) agentMap.set(agent.agentType, agent)
}

Plugin agent 命名空间：{pluginName}:{namespace}:{agentName}。Plugin agent 的 frontmatter 中 permissionMode、hooks、mcpServers 被忽略（安全边界）。

5 Skills & Commands 加载

5.1 统一命令列表 — getCommands()

// src/commands.ts — loadAllCommands 合并顺序（数组顺序 = 匹配优先级）
return [
  ...bundledSkills,        // 内置 bundle
  ...builtinPluginSkills,  // 内置 plugin skills
  ...skillDirCommands,     // filesystem: managed → user → project
  ...workflowCommands,     // feature-flagged
  ...pluginCommands,       // plugin slash commands
  ...pluginSkills,         // plugin skills
  ...COMMANDS(),           // 内置 /compact /help 等
]

findCommand(name, commands) 用 Array.find —— 先出现在数组中的同名 command 获胜。因此 bundled/builtin 优先于 filesystem，filesystem 优先于 plugin，plugin 优先于内置 slash commands。

5.2 Filesystem Skills 扫描

src/skills/loadSkillsDir.ts：

  • 目录：skills/<skill-name>/SKILL.md（新布局）+ legacy commands/*.md
  • Scope 路径：getSkillsPath(source, dir) 映射 managed/user/project
  • Lazy body load：列表阶段只读 frontmatter（name、description、whenToUse）；模型调用时才加载完整 SKILL.md body
  • Conditional skills：frontmatter paths: glob — 文件被 touch 时才激活
  • Dynamic skills：文件操作过程中动态发现，通过 getDynamicSkills() 追加

5.3 Skill frontmatter 关键字段

字段用途
nameskill / command 名称
description模型可见描述
when-to-use / whenToUse使用场景提示
paths条件激活 glob
disable-model-invocation禁止模型自动调用
contextinline（默认）或 fork（spawn subagent）
agentfork 模式使用的 subagent type

  1. Marketplace 已安装 plugins

6.4 三层 Refresh 模型

refresh.ts 注释

Layer 1: intent (settings) → Layer 2: materialization (~/.claude/plugins/) → Layer 3: active components (AppState)

refreshActivePlugins() 清除所有 plugin cache，重新加载 commands/agents/hooks/MCP/LSP，更新 AppState，递增 mcp.pluginReconnectKey 触发 MCP 重连。

8 Memory & Rules（CLAUDE.md）

8.1 加载顺序（低 attention → 高 attention）

src/utils/claudemd.ts 文件头注释：

  1. Managed CLAUDE.md + managed .claude/rules/
  2. User ~/.claude/CLAUDE.md + ~/.claude/rules/
  3. Project：cwd → root walk，每目录检查 CLAUDE.md、.claude/CLAUDE.md、.claude/rules/*.md
  4. Local CLAUDE.local.md

后加载的文件在 prompt 中位置更靠后 → 模型 attention 更高。

8.2 Rules 条件激活

.claude/rules/*.md 支持 frontmatter paths: glob。与 conditional skills 类似，文件被 read/edit/write 时通过 src/utils/attachments.ts 懒注入 nested_memory attachment。

8.3 @include 指令

Memory 文件支持 @path 语法引入其他文件（leaf text node only，防循环引用）。

8.4 注入时机

  • Session boot：getUserContext() memoized prefetch
  • Per file touch：getAttachmentMessages() 遍历 CWD→target 路径注入 nested rules
  • Compact 后：可能 clear getUserContext cache，SessionStart hooks 重建

11 优先级速查表

扩展类型冲突策略优先级（高者胜 / 先匹配）
SettingsDeep merge + policy first-winspolicy > flag > local > project > user > plugin
AgentsMap overwrite（后写覆盖）managed > flag > project > user > plugin > built-in
Commands/SkillsArray.find（先注册先匹配）bundled > fs(managed→user→project) > plugin > built-in /commands
MCPObject.assign（后覆盖前）local > project > user > plugin；enterprise 独占
CLAUDE.md/RulesConcat（后段 attention 更高）local > nearer dir > farther dir > user > managed
Plugins (同名)Project/session 覆盖 installedsession --plugin-dir > installed（除非 managed-locked）

关键差异

Agents 和 Commands 的冲突策略相反：Agents 是"后者覆盖前者"，Commands 是"前者屏蔽后者"。设计意图：Agent 允许项目定制覆盖内置；Command 让 bundled/内置安全命令不被 plugin 同名劫持。
