Claude Code 大 / 小模型搭配架构

基于 claude-code-rev 源码梳理：主循环大模型 + 侧信道小模型（Haiku）+ 同模型 Fork 侧任务。

源码路径：C:\Users\Harry\cursor_workspace\public\claude-code-rev

Small Fast = Haiku Main Loop = Opus / Sonnet 静态选型，非智能路由 Fork 复用 Prompt Cache

01核心结论

一句话

Claude Code 没有统一的“智能路由器” 在运行时决定大/小模型；而是按调用点静态选型：主对话走大模型，轻量侧任务走 Haiku（Small Fast Model），需要长上下文的重侧任务则 Fork 主模型 以复用 Prompt Cache。

  • 大模型 = mainLoopModel（默认 Opus 或 Sonnet，取决于订阅）
  • 小模型 = getSmallFastModel()（默认 Haiku 4.5，可被环境变量覆盖）
  • 中间档 = 少数场景显式指定 Sonnet（如 memory 相关性）；Fast Mode 是 Opus 的加速档，不是换小模型

① 主循环大模型

getMainLoopModel()

对话、工具调用、规划、写码。Max/Team Premium 默认 Opus 4.6，其余默认 Sonnet 4.6。

Opus ≈ $5/$25 · Sonnet ≈ $3/$15（per MTok）

② Small Fast 小模型

getSmallFastModel() / queryHaiku()

标题、标签、命令前缀、WebFetch 二次提取等廉价侧任务。thinking 关闭，通常无 tools。

Haiku 4.5 ≈ $1/$5（per MTok）

③ Fork 同模型侧任务

runForkedAgent()

Compact、Session Memory、Prompt Suggestion 等故意不用 Haiku，而是复用主模型 + Prompt Cache，避免 cache bust。

边际成本低（命中 cache）

03模型解析层

Small Fast Model

// src/utils/model/model.ts
export function getSmallFastModel(): ModelName {
  return process.env.ANTHROPIC_SMALL_FAST_MODEL || getDefaultHaikuModel()
}

queryHaiku() 内部强制 model: getSmallFastModel()，并关闭 thinking、清空 tools：

// src/services/api/claude.ts — queryHaiku
thinkingConfig: { type: 'disabled' },
tools: [],
options: { model: getSmallFastModel(), ... }

主循环模型优先级

  1. 会话内 /model 覆盖
  2. 启动 --model
  3. ANTHROPIC_MODEL 环境变量
  4. 用户 settings
  5. 订阅默认：Max / Team Premium → Opus；Pro / Enterprise / Team Standard / PAYG → Sonnet

易混淆：Fast Mode ≠ 小模型

fastMode 是在 同一 Opus 上走 API speed: 'fast'，单价更高（约 $30/$150），目的是加速，不是切到 Haiku。

为何重侧任务不用小模型？

forkedAgent.ts 注释写明：API cache key 由 system / tools / model / messages 前缀 / thinking 组成。换 Haiku 会直接 bust cache；对已经很长的会话，用主模型 fork + cache hit 往往比换小模型更省。

小模型任务特征

  • 短输入 / 短输出：标题、标签、前缀，不需要深度推理
  • 可失败：标题生成失败返回 null，或走启发式 fallback
  • 不进主对话历史：侧信道调用，不污染主 context
  • 能力边界：Haiku 不支持 tool_reference（见 toolSearch.ts）

07路由决策方式

原则

静态按调用点选型，不是运行时分类器在大/小模型之间动态切换。

getMainLoopModel() ├─ user / settings / env / --model ├─ allowlist filter └─ subscription default (opus vs sonnet) getRuntimeMainLoopModel() └─ permissionMode + opusplan / haiku 规则 getSmallFastModel() └─ ANTHROPIC_SMALL_FAST_MODEL || Haiku default ▲ queryHaiku() 始终走这里 sideQuery({ model }) └─ 调用方显式传入 · classifier → 默认 mainLoop · memdir → Sonnet · session_search → Small Fast runForkedAgent() └─ 故意不换 model，复用 parent CacheSafeParams getAgentModel() └─ inherit | alias | CLAUDE_CODE_SUBAGENT_MODEL

少数动态 / Flag 路由

  1. WebSearch：GrowthBook tengu_plum_vx3 → Haiku vs mainLoop
  2. Token count：部分 provider 条件升 Sonnet
  3. 3P unavailable：建议降级到上一版本
  4. Legacy Opus remap：1P 上 4.0/4.1 静默映射到当前 Opus
  5. Auto-mode two-stage：同一 classifier 模型上 stage1/stage2 提示变体，不是换 Haiku

08成本与缓存策略

成本优化手段

  1. 侧任务用 Haiku（标题、标签、前缀、WebFetch 提取）
  2. 重侧任务 Fork 主模型 + 共享 Prompt Cache（compact / memory / suggestions）
  3. Haiku 可单独关 caching（DISABLE_PROMPT_CACHING_HAIKU）
  4. Bedrock 小模型可独立 AWS region
  5. Away summary / side question：skipCacheWrite: true
  6. Bash prefix extractor：LRU 缓存，失败 eviction，避免重复 Haiku 调用

失败降级

场景行为
Title / Summary Haiku 失败返回 null / 启发式 fallback
Token count Haiku 不可用升 getDefaultSonnetModel()
Compact cache-sharing 失败streaming fallback（仍用 mainLoopModel）
Classifier API 错误fail-closed：阻塞执行
Subagent inherit走 runtime 解析（含 opusplan）

10设计要点总结

  1. 配对模型是「主循环大模型 + 侧信道 Haiku」，不是动态 LLM Router。
  2. Small Fast Model 是官方抽象（ANTHROPIC_SMALL_FAST_MODEL），实现默认 Haiku 4.5。
  3. Fast Mode ≠ 小模型：是 Opus 的 API speed 档，更贵更快。
  4. 昂贵上下文任务（compact / memory）故意用大模型 fork，用 prompt cache 省钱，而不是换 Haiku。
  5. 选型原则：短、可丢、无工具 → Haiku；长上下文、需 cache / 深度推理 → 主模型；少数精度敏感侧任务 → Sonnet。
  6. Subagent 默认可 inherit，也可钉 haiku / sonnet / opus；Guide agent 钉死 Haiku。

可借鉴到自研 Agent

把「主循环智能」和「辅助标签/前缀/标题」拆开；对需要读完整会话的后台任务，优先考虑与主模型共享 prompt cache，而不是机械地全部甩给小模型。
