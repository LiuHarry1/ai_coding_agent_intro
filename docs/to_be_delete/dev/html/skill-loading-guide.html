Skill 加载与调用

仅 src · 文件夹 + SKILL.md · 单一 Skill 工具 · inline / fork 双模式

Tool 提示词 paths 条件激活 调用入口 Subagent Deferred

1核心设计：文件夹 Skill + 单一调度器

Skill 是可复用的「流程模板」，以目录形式存放（不是 flat .md）。 与 Subagent 对称：多个 skill 合并进一个 Skill 工具，模型用 skill_name 选型。

图 1 · Skill 是目录；扫描只读 frontmatter，body 懒加载；执行分 inline / fork 两路

inline 默认模式

展开 SKILL.md body 后直接作为 tool result 返回。主 agent 在下一轮把它当「刚想起来的流程」继续执行。

fork 子 agent 模式

展开 body 后交给 runSkillFork：用指定 subagent 的 systemPrompt + 工具集，body 作为 user message 跑隔离 runAgent。

与 Agent 工具的区别

Skill 是用户/项目定义的流程模板；Agent 是内置/自定义的角色型 subagent。Fork skill 会借用 Agent 定义的工具裁剪逻辑。

2加载策略：每轮热加载 + 懒读 body

与 registerSubagents 对称：每次 chat 请求在 prepareChatTurn 里调用 registerSkills， 扫描磁盘与插件，合并后按需注册 Skill 工具。若无任何 active skill，则不注册该工具（避免空目录浪费 token）。

图 2 · 每 chat turn 扫描 + merge + paths 过滤；无 active skill 时不注册 Skill 工具

优先级（同名 skill 后者覆盖）

来源路径优先级
plugin .ai-agent/plugins/<name>/skills/<skill>/SKILL.md 最低；body 内 ${PLUGIN_ROOT} 会被替换
user ~/.ai-agent/skills/<skill>/SKILL.md 中
project <ancestor>/.ai-agent/skills/<skill>/SKILL.md 最高（深层 project 目录 > 浅层）
merge 顺序：mergeSkillsByName(pluginSkills, diskSkills) — 列表按优先级从低到高传入，后者覆盖前者。 Skill 名称来自文件夹名，frontmatter 不支持 name: 覆盖。

3SKILL.md 格式与 SkillDefinition

# .ai-agent/skills/code-review/SKILL.md
---
description: Run a structured code review checklist before opening a PR.
context: inline          # inline（默认）| fork
agent: general-purpose   # context: fork 时指定 subagent_type
arguments: "branch"       # 启用 $branch / $1 / $ARGUMENTS
paths: "src/**, tests/**"  # 可选；条件激活（见第 4 节）
---

# Markdown body = 流程正文（lazy load）
Review the diff on branch $branch …
Use scripts in ${SKILL_DIR}/checklist.md …
Frontmatter映射说明
（文件夹名）name唯一标识；斜杠 /code-review 与 tool skill_name 用它
descriptiondescription必填；写入 Skill 工具目录 + system-reminder 列表
contextcontextinline 或 fork，默认 inline
agentagentfork 目标 subagent；默认 general_purpose（须与已注册 agentType 匹配）
argumentsargumentNames声明命名参数，供 $name 替换
pathspathsgitignore 风格；有条件才激活（见下节）
bodyloadBody()扫描时不加载；invoke 时读取并 strip frontmatter

4条件激活：paths: 过滤

带 paths: 的 skill 是条件 skill：只有本轮「候选文件」与其 pattern 匹配时才进入 activeSkills， 才会注册进 Skill 工具并出现在 system-reminder 列表。

图 3 · 从用户输入提取路径 token，与 skill 的 paths pattern 做 gitignore 匹配

候选路径提取：utils/processUserInput/path_candidates.ts — 反引号内路径 + bare 形如 src/foo.ts 的 token。 日志会打印 (+N conditional hidden) 表示本轮被隐藏的 conditional skill 数量。

5展开管道：expandSkillBody

Skill 工具、斜杠命令、HTTP invoke 三条路径共用同一展开逻辑（skills/expand.ts），保证字节级一致。

1
loadBody() 懒读 SKILL.md，gray-matter 去掉 frontmatter。
2
substituteArguments $ARGUMENTS、$1、$name（与 slash command 同一套）。
3
expandInlineDirectives !`shell` 执行命令、@file 嵌入文件内容。
4
${SKILL_DIR} 替换为 skill 文件夹绝对路径（Windows 转 forward slash）。
5
preamble Base directory for this skill: … 前缀 + expanded body → combined。

6createSkillTool 工具提示词

工具名 Skill（SKILL_TOOL_NAME）。description 为固定模板 + 动态 validSkills 列表。 完整 skill 目录还通过 <system-reminder> 注入对话（见第 7 节）。 

Invoke a reusable skill — a parameterized procedure the user (or this project) has defined for repeatable workflows.

Important:
- Available skills are listed in <system-reminder> messages in the conversation.
- When a skill matches the user's request, invoke the relevant skill BEFORE generating any other response.

Two execution modes:
- **inline** skills return their expanded body as the tool result. Use them when you want to *remember* a procedure mid-thought …
- **fork** skills run as a fresh subagent with the body as system prompt. Use them when the skill needs many tool calls …

Arguments:
- `skill_name`: one of [code-review, canvas, …]   ← 动态 enum
- `arguments`: raw argument string (optional). Substituted into the skill body as `$ARGUMENTS`, `$1`, or `$name` …

Prefer skills over reinventing a procedure inline — they encode user/project conventions.
参数.describe() 原文
skill_name Which skill to invoke. Must be a registered skill name.
arguments Raw argument string. Substituted via $ARGUMENTS / $1 / $name. Pass an empty string if the skill takes none.
注意：description 里 fork 模式写「body as system prompt」是简化表述。 实际 runSkillFork 使用 target agent 的 systemPrompt，展开后的 combined 作为 runAgent 的 user message。

7Skill 列表注入主 agent

prepareChatTurn 用 formatSkillListing(activeSkills) 生成紧凑目录， 作为 skillListing 传给 runAgent，在首轮以 synthetic user message 注入： 

<system-reminder>
The following skills are available for use with the skill tool:

- code-review (inline): Run a structured code review checklist…
- canvas (inline): A Cursor Canvas is a live React app…
</system-reminder>

预算感知：默认约 8000 字符，或 context window 的 1%（formatSkillListing）。 超出时截断各 skill 的 description。与 deferred tools 列表可合并进同一条 reminder。

斜杠 inline 的特殊处理

若 skill body 未消费 $ARGUMENTS（参考型 skill 如 /pdf），dispatcher 会在 expanded body 后追加 ---\n\nUser request: …，避免用户意图被静默丢弃。

11设计要点回顾

文件夹 ≠ flat md

Skill 是 <name>/SKILL.md 目录，可 bundling 脚本与资源；Agent/Command 才是 flat .md。

懒加载 body

扫描只 parse frontmatter（16KB 上限）；100+ skill 也不拖慢每轮 register。

无 skill 无工具

activeSkills.length === 0 时不注册 Skill 工具，模型看不到空 dispatcher。
