Session Compacting 图文详解

长对话如何省 context：从预警 → Micro-compact（轻度）→ Full compact（LLM 摘要）→ Reactive aggressive（报错兜底）

1每个 Agent Step 开始前都会检查

入口：runAgent → runCompactionAndLog → compactIfNeeded（services/compact/autoCompact.ts）

图 1 · 四级机制：Warning（不改 messages）→ Micro → Full → 正常继续

2阈值怎么算？（默认 200K context）

配置在 ~/.ai-agent/config.json 的 compaction 段，也可用环境变量覆盖。

fullThreshold = contextWindow − 20_000 − 13_000
                = 200_000 − 33_000 = 167_000 tokens

microThreshold = fullThreshold − 27_000 = 140_000 tokens

warning 当 tokens ∈ [147_000 , 167_000) → 发 compaction_warning 事件
配置项默认值含义
compaction.enabledtrue关闭则跳过 proactive（DISABLE_AUTO_COMPACT=1 同理）
contextWindow200_000模型 context 上限，用于算阈值
microCompactKeepRecent5Micro 时保留最近 N 条 tool 消息完整载荷
maxFilesToRestore5Full compact 后从磁盘恢复的文件数上限
maxTokensPerFile5_000每个恢复文件 token 上限
fileBudget50_000所有恢复文件合计 token 预算
环境变量覆盖（getCompactionConfig）： DISABLE_COMPACT=1 / DISABLE_AUTO_COMPACT=1 关闭 proactive； COMPACT_CONTEXT_WINDOW 覆盖 contextWindow（影响阈值）； COMPACT_MICRO_KEEP 覆盖 micro 保留条数。 注意阈值常量（20K / 13K / 27K / 20K）是代码内常量，不可由配置改。

图 2 · token 区间与触发的 compact 级别

3Micro-compact（轻度压缩 — 你说的 minor）

代码名 microCompact，不调 LLM，只替换旧 tool 消息的载荷文字，保留 message 骨架和 tool_call ↔ tool_result 配对。

🟢 读类工具 → 清 OUTPUT

tool result 被替换（CLEARABLE_TOOL_RESULTS）

  • read_file · grep · glob
  • bash · shell · powershell
  • web_fetch · web_search

🟢 写类工具 → 清 INPUT

assistant 里 tool-call 的 args（CLEARABLE_TOOL_INPUTS）

  • write_file · edit_file
  • create_file · apply_patch · NotebookEdit
  • 保留 tool-call 结构，input 变占位 JSON

🟢 保留最近 N 条

默认 N = 5

  • 从后往前数 role=tool 消息
  • aggressive 模式 N = 1

Micro-compact 前后 messages 示意（keepRecent=2）

tool #1
read result → "[Old tool result content cleared to save context]" 或磁盘引用占位
tool #2
grep result → cleared / 磁盘引用
tool #3
read result → 完整文件内容（保留）
tool #4
bash result → 完整 stdout（保留）

图 3 · 消息条数不变，只「掏空」旧 payload；最近 2 条 tool 消息原样保留

Sidecar 磁盘卸载（tool-storage）：被清掉的大输出会先写到 .sessions/{sessionId}/tool-results/{toolCallId}.txt， tool result 里换成 <persisted-output path="…"> 引用。 模型需要时可 read_file 那条路径取回全文。 （执行时超过 32KB 也会提前 persist，但本 turn 仍返回完整内容。）

4Full compact（LLM 全量摘要）

当 micro 后仍 ≥ fullThreshold（或 force / aggressive）触发。 整段 history 被替换成 1 条 user 消息，内含结构化摘要 + 可选文件恢复 + todo。

图 4 · Full compact = 用 LLM 写摘要，重建极简 context

摘要章节（<summary> 内）保留什么
Primary Request / User Messages用户意图、原话
Files and Code Sections改过的文件、关键 snippet
Errors and Fixes踩坑与修复
Pending Tasks / Current Work进行中的任务
Full compact 之后 agent.ts 还会 attachTodoReminderAfterCompaction： 若 todo 列表非空，把 reminder 追加到最后一条 assistant 的 text 上（full compact 后通常只有 user 消息，此逻辑主要防 edge case）。
Prompt-Too-Long 自救（summarizer 自身超长）： 若摘要这一次 generateText 调用本身报 413 / context length / too long （isLikelyTooLong），会丢弃最旧 30% 消息 （slice(floor(len*0.3))）后重试。最多重试 MAX_SUMMARIZE_RETRIES = 1 次； 仍失败则抛错，由上层熔断器计数。另外 compactConversation 在 messages < 2 时直接返回 null（不压缩）。
恢复哪些文件？extractRecentlyReadFiles 从后往前扫 assistant 的 read_file tool-call，取最近去重的文件路径； restoreRecentFiles 跳过目录与 > 512KB 的文件，逐个读盘，单文件超 maxTokensPerFile 截断，合计受 fileBudget 限制。

5Reactive Aggressive（API 报错兜底）

当 streamText 抛出 context length / too long 错误，不等阈值，立刻强制压缩。

🔴 触发条件

  • isContextLengthError(err)
  • 413 / "context length" / "too long"
  • 仅首次重试（ctxLengthAttempt === 0），发 compaction_reactive 事件

🔴 aggressive micro

  • keepRecent = 1
  • 只留最后 1 条 tool 完整载荷

🔴 必做 full

  • force: true
  • aggressive: true
  • 同一请求重试 streamText
熔断器：连续 full compact 失败 ≥ 3 次 → 暂停 proactive compact（MAX_CONSECUTIVE_FAILURES），避免死循环。

6三级 Compact 对照表

Warning Micro-compact Full compact
是否改 messages 否 是（替换 payload） 是（整段替换为 1 条）
是否调 LLM 否 否 是（summarizer）
典型触发 token 147K – 167K ≥ 140K ≥ 167K（micro 后仍超）
消息条数 不变 不变 大幅变少（→ 1）
事件名 compaction_warning compaction_micro compaction_start / compaction_done
代码 autoCompact.ts microCompact.ts compact.ts

7Compact 之后会怎样？

discoveredTools 不受影响 — 存在 session 对象里，不随 messages 压缩而丢失。

Full compact 会清掉 history 里的 skill body / tool_search 文字 — 摘要里会尽量保留关键信息；若摘要漏了，模型可能需重新 skill() 或 tool_search。

Micro 不会删 listing — 只清 tool 载荷；<system-reminder> 的 user 消息一般保留（除非 full compact 整段重写）。

8一句话记住

Micro = 掏空旧 tool 输出/输入（便宜、每 step 可跑）→ Full = LLM 写摘要 + 恢复最近文件（贵、history 变短）→ Reactive = 报错时 aggressive 版 Full。
