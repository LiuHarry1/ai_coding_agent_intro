# Features

Last verified: 2026-09-13

## Overview

This section documents user-facing capabilities implemented by the current
agent, including scheduled work, permissions, extensions, code intelligence,
and context-efficient execution.

## How it works

The HTTP, Electron, CLI, and ACP entry points converge on the same session, tool, and wire-protocol types. Workspace settings are resolved for the active `cwd`; feature-specific services then enforce those settings before work reaches the agent loop.

- [Scheduled tasks](scheduled-tasks.md) run prompts later in an existing session.
- [Permissions](permissions.md) gate filesystem tools by workspace, rules, and deployment mode.
- [Attachments](attachments.md) project files, images, diagnostics, plans, and internal context into model messages.
- [Primary agents](primary-agents.md) replace the main-thread profile without becoming a subagent.
- [Slash commands](slash-commands.md) unify built-ins, Markdown commands, and skills.
- [Background tasks](background-tasks.md) keep long shell commands out of the blocking agent path.
- [LSP](lsp.md) provides structured code intelligence through the execution worker.
- [Large tool outputs](tool-storage.md) persist full payloads while keeping model context bounded.

## Configuration

Most feature configuration lives in user or project `.ai-agent/settings.json`. Markdown extensions live below `.ai-agent/agents/`, `.ai-agent/commands/`, or `.ai-agent/skills/`. Managed deployment policy is loaded from the platform managed directory and has the highest extension precedence.

## Failure modes and security notes

- Settings are schema-validated; unsupported values can reject the settings file.
- SSO forces a non-interactive filesystem boundary, but shell commands are not an OS sandbox.
- Feature availability may differ by workspace because settings and extensions are resolved from the active `cwd`.
- Internal attachments are trusted context generated by the host; user-provided paths and uploads still pass validation.

## Source map

- `src/core/settings-schema.ts` — supported settings surface.
- `src/core/types.ts` — shared session, agent, attachment, and configuration types.
- `src/utils/markdownConfigLoader.ts` — user, project, managed, and plugin extension loading.
- `src/server/router.ts` — HTTP feature routing.
- `protocol/README.md` — transport-independent client protocol.
