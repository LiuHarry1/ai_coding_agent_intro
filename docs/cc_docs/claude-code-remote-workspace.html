01 结论速览

CC 里「远程」不是单一模块，而是 四条并行路径。「指定远程 workspace」的方式因路径而异。

路径入口Agent 跑在哪Workspace 怎么指定
CCR / Teleport --remote / --teleport Anthropic 云 / BYOC 容器 Git clone 或 git bundle；不传本机绝对路径
Remote Control (Bridge) claude remote-control / /remote-control 本机（子进程 CLI） 注册 directory = cwd；spawn cwd: dir / worktree
SSH claude ssh <host> [dir] SSH 远端主机 位置参数 [dir] 或 sshConfigs[].startDirectory
Direct Connect cc:// / cc+unix:// Peer server 进程 POST /sessions 带 { cwd }，可回 work_dir
关键结论

真正「连到某一台电脑 + 指定该机上某个目录」的，主要是 SSH 与 Bridge（本机充当环境）。CCR 是连到云端环境，workspace 由 git/bundle 物化。

03 SSH：指定远程电脑 + workspace

用户入口

claude ssh <host> [dir]
claude ssh my-devbox ~/projects/foo
claude ssh --permission-mode auto my-devbox /tmp/work
claude ssh --local /some/dir   # e2e：跳过真实 ssh

解析位置：src/main.tsx（feature SSH_REMOTE）

Settings 默认 workspace

sshConfigs?: Array<{
  id, name, sshHost, sshPort?, sshIdentityFile?,
  startDirectory?: string  // 远端默认 cwd，支持 ~；可被 CLI [dir] 覆盖
}>

src/utils/settings/types.ts

设计意图（main.tsx 注释）

  1. probe 远端是否已有 Claude binary
  2. 需要时 deploy binary
  3. ssh 带 unix-socket -R → 本机 auth proxy
  4. 交给 REPL 一个 SSHSession：Tools 远端、UI 本地
  5. setOriginalCwd(sshSession.remoteCwd) —— workspace 以远端 remoteCwd 为准

会话历史落在远端：~/.claude/projects/<cwd>/

本树缺口

src/ssh/createSSHSession.ts 为 stub（return {}），SSHSessionManager 为空类。useSSHSession.ts 期望完整 API。架构与 CLI/settings 契约齐全，运行时实现被剥空。

Workspace 不是本机路径

type SessionContext = {
  sources: SessionContextSource[]  // git_repository URL + revision
  cwd: string

teleportToRemote 物化顺序：

  1. 探测本地 repo → git_repository source

08 端到端时序

A. 连某台开发机上的某个目录 —— SSH

User: claude ssh devbox ~/src/app → parse host + dir → createSSHSession({ host, cwd }) → probe/deploy + ssh -R auth proxy → remoteCwd 写回本地 state → launchRepl(sshSession) → useSSHSession：UI 本地，工具远端

B. 让某台电脑可被网页远程使用 —— Bridge

On target machine: cd /path/to/workspace claude remote-control --spawn worktree --capacity 4 → POST /v1/environments/bridge { directory: /path/to/workspace } → poll work → spawn child with cwd=dir|worktree On phone / another laptop / claude.ai: open session targeting that environment → backend enqueue work → bridge picks up → agent runs on target machine workspace

C. 云端沙箱 —— CCR

claude --remote "fix the flaky test" → pick environment_id → POST /v1/sessions + git/bundle context → container clone → worker → local WS subscribe（或打印 resume URL）

12 一句话总结

Bottom line

指定「某台电脑 + 某个目录」：产品契约在 claude ssh <host> [dir]（startDirectory）与 claude remote-control 的 directory / spawn cwd。

云端远程：走 CCR teleport，workspace 由 git/bundle + environment_id 决定。

本地 UI、远程执行 是所有路径的共同分层；workspace 只是各路径在 create / register / spawn 时写入的不同字段。
