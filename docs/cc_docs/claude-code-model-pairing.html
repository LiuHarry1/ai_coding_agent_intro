Claude Code：大模型 / 小模型搭配策略

基于 claude-code-rev 源码的架构解读：主对话用强模型，旁路任务用小快模型。

源码路径：C:\Users\harry.liu\cursor_workspace\public\claude-code-rev

Small Fast = Haiku Main Loop = Sonnet / Opus Side Query = 按任务选模型

01 总览

Claude Code 不是「一个请求里动态路由大/小模型」，而是把模型分成两条明确通道：

Main
Loop
主循环模型 getMainLoopModel() 负责对话、工具调用、规划、写代码、上下文压缩等「智能主路径」。默认：Max/Team Premium → Opus；其余 → Sonnet。
Small
Fast
小快模型 getSmallFastModel() 默认 Haiku 4.5，可用 ANTHROPIC_SMALL_FAST_MODEL 覆盖。负责标题、摘要、命令前缀、网页抽取、token 探测等「辅助旁路」。
Selective
Mid
中间档（少数场景显式选 Sonnet） 例如记忆相关性筛选用 getDefaultSonnetModel()——比 Haiku 更准，但不必占用主循环的 Opus 成本。

一句话

主路径用贵而强的模型；所有「短、结构化、可失败」的旁路任务统一落到 Small Fast（Haiku），必要时再用 Sonnet 做判断任务。

02 双通道架构

用户输入 │ ├─► Main Loop（query / agent loop） │ model = getMainLoopModel() ← Opus / Sonnet │ tools, thinking, compact… │ └─► Side / Helper 调用（并行或穿插） ├─ queryHaiku() ← 永远 Small Fast └─ sideQuery({ model }) ← 调用方自选： Haiku / Sonnet / Main

核心函数（model.ts）

// 小快模型：旁路默认值
export function getSmallFastModel(): ModelName {
  return process.env.ANTHROPIC_SMALL_FAST_MODEL || getDefaultHaikuModel()
}

// 主循环模型：用户配置 → 订阅档默认
export function getMainLoopModel(): ModelName {
  const model = getUserSpecifiedModelSetting()
  if (model !== undefined && model !== null) {
    return parseUserSpecifiedModel(model)
  }
  return getDefaultMainLoopModel()
}

// Haiku 默认（全平台 Haiku 4.5）
export function getDefaultHaikuModel(): ModelName {
  if (process.env.ANTHROPIC_DEFAULT_HAIKU_MODEL) {
    return process.env.ANTHROPIC_DEFAULT_HAIKU_MODEL
  }
  return getModelStrings().haiku45
}

03 两个 API 入口

queryHaiku 在 services/api/claude.ts。强制 model: getSmallFastModel()， thinking: disabled，tools: []，走完整 query 管道但不流式。 适合标题、摘要、解析、抽取。
sideQuery 在 utils/sideQuery.ts。轻量旁路 API：自带 OAuth fingerprint、attribution、betas、 model 规范化。调用方传入任意 model。适合分类器、权限解释、记忆筛选、会话搜索。 
// queryHaiku：模型写死为 Small Fast
await queryModelWithoutStreaming({
  ...
  options: {
    model: getSmallFastModel(),
    enablePromptCaching: options.enablePromptCaching ?? false,
    ...
  },
})

// sideQuery：模型由调用方决定
await sideQuery({
  querySource: 'session_search',
  model: getSmallFastModel(),   // 或 getDefaultSonnetModel() / getMainLoopModel()
  system, messages, ...
})

注意

permissionExplainer.ts 注释写「using Haiku」，实际代码是 getMainLoopModel()——以代码为准。旁路不一定等于小模型。

怎么选

一定用小模型、无 tools → queryHaiku； 要自选模型 / tools / tool_choice → sideQuery({ model })； 主循环与 compact → 不走这两个。

07 运行时切换与特殊规则

getRuntimeMainLoopModel

同一会话内，主模型可随 permission mode 临时切换：

// opusplan：Plan 模式用 Opus，平时用 Sonnet
if (getUserSpecifiedModelSetting() === 'opusplan'
    && permissionMode === 'plan' && !exceeds200kTokens) {
  return getDefaultOpusModel()
}

// 用户选了 haiku：Plan 模式升到 Sonnet
if (getUserSpecifiedModelSetting() === 'haiku'
    && permissionMode === 'plan') {
  return getDefaultSonnetModel()
}

return mainLoopModel

Subagent 模型继承

utils/model/agent.ts：默认 inherit；Bedrock 下会继承父模型的跨区域前缀（如 eu. / us.），避免 IAM 区域权限踩坑。

Haiku 能力限制

  • toolSearch.ts：Haiku 不支持 tool_reference；子代理用 Haiku 时需注意与 session 模型能力差。
  • Thinking：1P/Foundry 上 Claude 4+（含 Haiku 4.5）可开；Bedrock/Vertex 上仅 Opus/Sonnet 4+。
  • queryHaiku 路径明确关闭 thinking，保持旁路廉价稳定。

Bedrock 小模型独立区域

// services/api/client.ts
const awsRegion =
  model === getSmallFastModel()
  && process.env.ANTHROPIC_SMALL_FAST_MODEL_AWS_REGION

主模型与小模型可以落在不同 AWS 区域——旁路流量可单独部署/限流。

08 设计原则（可复用）

  1. 按任务切模型，不按 token 动态路由。 主路径固定强模型；旁路固定小模型。避免复杂 router，行为可预测。
  2. 旁路任务特征： 短输入、短输出、结构化（JSON / tool_choice）、可失败降级、高频、对延迟敏感。
  3. 质量敏感任务不降档： Compact、安全分类、主 Agent 推理留在主模型。
  4. 中间档留给「判断但不行动」： 如记忆筛选用 Sonnet——只做选择，不写代码、不改仓库。
  5. 统一抽象 + 可覆盖： getSmallFastModel() 一处定义；env / settings / feature flag / hook.model 可覆盖。
  6. 两个出口： queryHaiku（傻瓜式旁路）vs sideQuery（自选模型的旁路）。新功能优先走这两个，不要直接裸调 SDK。
  7. 探测性请求必须用最便宜模型： API key verify、quota check、token count——否则自己把自己打贵。

对 AI Coding Agent 的启示

若要在自研 Agent 里做「大小模型搭配」，可直接对齐 CC： mainLoopModel + smallFastModel 双配置； 旁路 helper API；场景白名单决定走哪条通道； compact / safety 永不降级。
