OpenCode 大 / 小模型搭配架构

基于 public/opencode 源码梳理：会话主模型 + 极窄 utility 小模型；compact / explore 默认仍走主模型。

源码路径：C:\Users\Harry\cursor_workspace\public\opencode

model = 主循环 small_model = 工具模型 静态选型，非智能路由 小模型职责很窄

01核心结论

一句话

OpenCode 没有运行时智能路由。它用调用点静态选型：会话 model 跑主 agent / 多数子任务 / compaction；getSmallModel()（配置 small_model 或自动挑 haiku/flash/nano）只服务极少数轻量侧任务（会话标题、项目副本命名）。

  • 主模型 = 配置 model / 会话当前模型（Sonnet、Opus、GPT-5、Gemini Pro 等）
  • 小模型 = small_model 或 Provider.getSmallModel() 自动匹配
  • 第三轴 = variant（推理力度 high/low/none…），不是大小档切换

和 CC 的最大差异

Claude Code 有大量 Haiku 侧信道 + compact 用主模型 fork 保 cache；OpenCode 的小模型通道非常薄——compact / explore / general 默认都烧主模型，除非用户用 agent.*.model 自己改。

① 会话主模型

config.model / session model

build、plan、工具循环、默认的 explore/general/compaction 都走它。

用户自选：Sonnet / Opus / GPT-5 …

② Small / Utility

getSmallModel()

几乎只用于标题生成、项目副本短名。自动优先 haiku / flash / nano。

配置："small_model": "anthropic/claude-haiku-4-5"

③ Agent 覆盖 + Variant

agent.*.model / variant

用户可把 plan/explore/compaction 钉到便宜模型；variant 只调推理力度，不换模型档。

可选成本优化入口

03模型解析

配置（opencode.json）

{
  "model": "anthropic/claude-sonnet-4-5",
  "small_model": "anthropic/claude-haiku-4-5",
  "agent": {
    "explore": { "model": "anthropic/claude-haiku-4-5" },
    "compaction": { "model": "anthropic/claude-haiku-4-5" },
    "title": { "model": "anthropic/claude-haiku-4-5" }
  }
}

主模型优先级

  1. CLI --model / -m
  2. 配置 model
  3. 最近使用模型（state 里的 model.json）
  4. 目录排序优先：gpt-5 → claude-sonnet-4 → big-pickle → gemini-3-pro

小模型：Provider.getSmallModel

// packages/opencode/src/provider/provider.ts
// 1) config.small_model（解析失败则 undefined，不继续自动匹配）
// 2) plugin hook: experimental.provider.small_model（如 Copilot utility）
// 3) 按 provider 目录子串优先匹配：
//    默认: claude-haiku-4-5 → 3-5-haiku → gemini-*-flash → gpt-5-nano
//    opencode*: gpt-5-nano
//    github-copilot*: gpt-5-mini → haiku → 默认列表
//    Bedrock: 优先 global./us./eu. 前缀

注意

若显式配置了无效的 small_model，会返回 undefined，不会再回落到自动 haiku 列表。标题生成随后会退回会话主模型。

small: true ≠ 换模型

流式请求上的 small: true 走 ProviderTransform.smallOptions()：跳过用户 variant、减弱/关闭 reasoning、OpenAI 系设 store: false。它是请求模式标志，模型 ID 仍由调用方传入。

Variant ≠ 大小模型

high / max / low / none 等 variant 只调节同一模型上的推理预算，是正交于「大/小模型」的第三轴。

04大模型（主模型）做什么

角色：会话主脑。primary agent（build/plan）的工具循环几乎都跑在 session model 上。

任务说明选型关键路径
主对话 + 工具循环 读改文件、Bash、搜索、MCP 等 session model session/prompt.ts
Plan 模式 禁止编辑，做规划 session / agent.plan.model agent/agent.ts（plan）
Explore 子 agent 只读探索代码库；“fast”指权限/提示，不是换小模型 默认继承父模型 agent/agent.ts, tool/task.ts
General 子 agent 并行多步调研/执行 默认继承父模型 tool/task.ts
Context Compaction 上下文压缩；默认用当前用户消息的模型 session model（可覆盖） session/compaction.ts
Agent 配置生成 opencode agent 等结构化生成 defaultModel() agent generate 路径

Compaction 默认用主模型

compaction.ts：agent.model ?? userMessage.model。不像 CC 那样为了 prompt cache 刻意 fork 同模型——而是直接复用会话当前模型（可选 agent.compaction.model 改便宜模型）。

05小模型做什么

角色极窄：文档表述为 “lightweight tasks like title generation”。源码里实际调用点很少。

任务选型链文件
Session 标题 title agent.model → getSmallModel(provider) → 会话主模型；small: true session/prompt.ts → ensureTitle
Project Copy 短名 getSmallModel(defaultProvider) → default model；small: true .../handlers/project-copy.ts

标题生成流程

// session/prompt.ts — SessionPrompt.ensureTitle
const ag = yield* agents.get("title")
const mdl = ag.model
  ? yield* provider.getModel(ag.model.providerID, ag.model.modelID)
  : ((yield* provider.getSmallModel(input.providerID)) ??
     (yield* provider.getModel(input.providerID, input.modelID)))

yield* llm.stream({
  agent: ag,
  small: true,   // 减弱 reasoning，不决定 model ID
  tools: {},
  model: mdl,
  messages: [{ role: "user", content: "Generate a title..." }, ...],
})

小模型任务特征

  • 短输入 / 短输出（标题、2–3 词 slug）
  • 无 tools（permission 全 deny）
  • 可失败回退（project-copy 失败可走 slug）
  • 不承担 compact、分类、命令前缀、WebFetch 二次提取等（这些在 CC 里常给 Haiku）

summary agent

内置有 hidden summary agent 和 prompt/summary.txt，但当前未见 agents.get("summary") 的 LLM 调用接线；TUI 的 summarize/compact 走的是 compaction / 其它路径。不要把它当成活跃的小模型消费者。

06Agent 矩阵

OpenCode 用 agent 矩阵 而不是简单的大/小二元档。多数 agent 共享同一会话模型。

AgentModeHidden默认模型行为
buildprimary否会话 / 全局 model
planprimary否同上（禁编辑）
generalsubagent否继承父 assistant 模型，除非 agent.general.model
exploresubagent否同上；“fast”=只读+提示，非小模型
compactionprimary是会话用户消息模型，可覆盖
titleprimary是小模型链（见上）
summaryprimary是有定义，LLM 路径基本未接线

用户若想省钱，可显式配置，例如把 explore / compaction 钉到 Haiku——这是可选策略，不是默认。

07路由与 small 标志

原则

静态按调用点选型，没有分类器在大/小模型间动态切换。

主循环 └─ lastUser.model（会话当前模型） Subagent (Task tool) └─ subagent.model ?? 父 assistant 的 model + variant Compaction └─ compaction.agent.model ?? userMessage.model Title └─ title.agent.model ?? getSmallModel(provider) ?? session model + stream({ small: true }) Project copy name └─ getSmallModel(defaultProvider) ?? defaultModel + stream({ small: true }) llm/request.ts 当 small=true └─ 跳过用户 variant，套用 smallOptions（弱/无 reasoning）

少数动态点

  1. Plugin 注入 small model（GitHub Copilot utility models）
  2. 无效 small_model → undefined → 标题退回主模型
  3. Overflow → compaction 再继续（换上下文形态，不换更便宜模型）
  4. HTTP/限流重试：同模型重试，不是 “try cheaper model”

对照记忆

CC Haiku 侧信道 ≈ OpenCode 的 title + getSmallModel（但 OC 覆盖面小得多）。CC compact-for-cache ≈ OC compaction 用当前会话模型（同类尺寸，但不是 “为 cache 而 fork” 的叙事）。

09成本与缓存

已有优化

  1. 标题 / 命名用便宜小模型（haiku/flash/nano 或 Copilot utility）
  2. small: true 降低 reasoning 成本
  3. Auto-compact + 可选 tool-output prune 缩小上下文
  4. Anthropic / Bedrock 等 prompt cache markers（applyCaching）
  5. Variant 调低推理力度（同一模型）
  6. 用户可把 agent.explore.model / agent.compaction.model 设便宜模型

没有的东西（相对 CC）

  • 没有广泛的 Haiku 侧信道（命令前缀、fetch 提取、分类器…）
  • 没有 “fork 同模型保 cache 做 compact” 的专门封装
  • 没有订阅档位自动 Opus/Sonnet 默认阶梯
  • 没有 ANTHROPIC_SMALL_FAST_MODEL 等价物（用配置 small_model）
  • 失败重试不会自动降到更便宜模型

V2 方向

specs/v2/config.md：计划移除顶层 small_model；标题模型改为配置 title agent 的 model。当前运行时 small_model 的主要消费者就是标题生成。

11设计要点总结

  1. 配对很薄：主模型扛几乎一切；小模型只做标题/短名一类 utility。
  2. 静态选型：按调用点 / agent 配置决定，没有任务分类器。
  3. small: true 是请求选项，不是模型选择器；真正选小模型靠 getSmallModel。
  4. Compaction / Explore 默认烧主模型；想省钱要靠 agent.*.model 手动配置。
  5. Variant 是推理力度轴，与大/小模型正交。
  6. V2 将去掉 small_model，统一到 agent 级模型覆盖（尤其 title）。

可借鉴

若自研 Agent：至少把「标题/命名」从主循环拆到便宜模型；同时想清楚 compact / explore 是默认跟主模型（质量优先）还是默认跟小模型（成本优先）——OpenCode 选了前者，Claude Code 在侧任务上更激进地用 Haiku。
